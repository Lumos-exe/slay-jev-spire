# 整局游戏代理与复盘目标

用户说“开始新的一局”后，应用启动指定角色和难度的对局，完成战斗、地图、事件、奖励、商店、营火、升级删牌和其他选择，直到胜利或死亡。用户随时可以暂停。结束后保存完整决策时间线，调用大模型复盘，把经过整理的经验带进下一局。

## 一局的产物

每个决策记录当时可见的信息、合法候选、最终选择、模型与策略版本，以及执行后的实际状态。记录明确区分选择、发送、确认、取消和失败；模型没有提供的理由不能事后伪装成当时的理由。生命、金币、卡组变化可以观察，长期收益需要在后续事件中追踪。

整局报告包含结果、路线、卡组演变和关键决策。胜利或死亡来自游戏的结束状态；暂停、请求预算耗尽、错误或未支持界面是中断。日志可以很长，报告先按战斗或楼层汇总，再保留可展开的原始步骤。

## 复盘怎样影响下一局

复盘模型先阅读各段摘要，再针对重要节点检查原始记录，形成带证据的经验。每条经验保存适用条件、观察依据、推荐变化和不确定性。例如“在当前生命与卡组条件下，连续精英路线的风险偏高”比“永远避开精英”更有用。

下一局按角色、难度、卡组、遗物、生命和对手检索相关经验，作为决策上下文。经验和策略都保留版本，可以撤回。这里的学习首先通过持久记忆和策略更新实现；普通 API 请求不会自动更新模型权重。

对未走过的分支只能提出假设，不能把假想结局写成事实。策略是否改善，需要跨多局、多个种子比较胜率、推进楼层、资源利用和请求成本，不能靠单局输赢判断。

## 开发验收顺序

1. 支持跨战斗的有界执行，补齐所有界面和规则覆盖。
2. 从新局开始，真实完成到 GAME_OVER，保存可读、可追踪的整局记录。
3. 自动复盘并产生持久经验；验证下一局的模型输入确实包含相关经验。
4. 做多局对照，验证策略变化的效果和成本。
5. 打包可发布应用：配置 API、开始、暂停、恢复、预算管理、对局与复盘浏览。

当前已有真实单场战斗验证，以及奖励、地图、第 2 层战斗的衔接记录。通用原生铁甲卡牌、其他选择界面、显式新局、恢复和自动时间线已接入。限定规则的整轮候选、本地击杀校验、证据复盘和跨局经验检索已加入本地测试，并重算真实战斗快照。大模型自由复盘、多回合随机模拟及真实完整整局结束验证仍未完成，覆盖详情见 [整轮规划与经验](turn-planning.md)。
