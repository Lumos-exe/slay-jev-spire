## 已实现的纵向链路

### 原生身份 → 本局记录 → 控制器恢复

- 新原生桥接版本 0.4.0。BaseMod 的 `PreStartGameSubscriber` 为新局分配 UUID，`CustomSavable<String>` 将 RunId 写进原生存档，读档恢复该 RunId。
- 房间、战斗怪物组、怪物实例与奖励对象使用对象身份登记；同名怪物、同层奖励不再被当作同一个对象。控制器重启不会重建游戏对象，因此身份保持。
- 重新加载游戏存档会创建新的房间/奖励实例，它们获得新的实例 ID；旧奖励的 skip 不会套到重新创建的奖励上。这是有意的恢复边界。
- `GameIdentity` 校验原生身份。正式运行要求原生身份契约；离线旧快照仍可读取，但不允许依种子自动导入历史。
- 恢复只读取 `runs/<RunId 的 SHA256>/recovery.jsonl`；旧的全局 `runs.jsonl` 保留作审计，不再作为恢复数据源。
- 奖励过滤需要 RunId + RewardSourceId；缺少源 ID 时保留原生选项。
- 在途事务先核对所属实际游戏，再允许提交回执；控制器重启恢复本局已确认记忆及计数。启动命令中残留的 `--start-new` 不能覆盖实际 RunId。
- 原生事务协议与 `TransactionLedger` 的重投、接受、结算语义保持。

### 规范化模拟状态 → 可观察前置条件 → 原生动作绑定

- 把原来零散的投影字段集中到 `semantics.py`；记录卡牌类型、费用、一次性免费/消耗、保留、目标类型、升级资格/预览、手牌顺序，以及怪物实例和机制字段。
- 前置条件投影中未提供的字段保留 `None`。规则归一化中的历史缺省值仍需在下一阶段逐项审计，不能据此宣称整个模拟器已消除缺失值歧义。
- 新生成卡牌按已知原版默认值生成，并按实际手牌顺序绑定符号 UUID；不能因为 UUID 排序而交换同名复制牌的顺序。
- 观察不匹配时重新决策；不执行旧步骤后再等待后续错误。
- 这仍是从字典状态向正式领域模型的过渡：完整不可变 Observation/Transition/DecisionSegment 尚未迁移；搜索等价关系仍保留更多模拟历史，比执行前置条件更保守。

### 供应方能力与证据

- 独立 `ProviderCapabilities` 记录官方 Choice 上限 255，以及出处 URL。这是接口约束，不是策略超参数。
- 超过上限时进入显式模型分组协议，各候选进入一个分组，由模型选组内候选，再比较胜者。日志记录触发原因、完整组成员、胜者与决赛概率。
- 单次适配器入口也检查上限，避免其他调用路径绕过检查。
- 分组并不保证选出与全体一次比较相同的最佳项；这是需要单独评估的协议，不宣称拥有最优召回率。
- 传输边界记录实际 HTTP 请求/响应正文、状态码、DecisionId、RequestId、候选别名映射、耗时；不读取或记录 HTTP 鉴权头。成功和 HTTP 400 均有测试。
