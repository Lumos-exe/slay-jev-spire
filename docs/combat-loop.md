# Jev 自动完成一场战斗

当前支持铁甲战士的 Strike_R、Defend_R、Bash（未升级或升级一次），燃烧之血与
涅奥的悲恸，玩家与敌人的力量、敏捷、虚弱、易伤、脆弱，以及敌人的蜷身、仪式。
能力的 ID、名称与层数保留在模型摘要中；牌的效果说明是基础值，实际效果由游戏
规则计算。未知牌、能力、遗物或选择界面会停止自动操作。

## 启动与暂停

```powershell
& .\tools\setup_communication_mod.ps1 -Combat -Mode jev -MaxDecisions 20
```

正常重启 Mod 模式游戏，继续对局。程序等待第一场支持的战斗，不会自动开始新局、
选择地图或处理奖励。默认最多 20 次模型请求，可配置 1–50；SDK 不自动重试。
每个新进程会重新获得一次战斗运行机会，验证完成后不带参数运行配置脚本，恢复
只采集配置。密钥继续使用已有的 Windows 本机加密文件或环境变量。

双击项目根目录 `pause_combat.cmd` 创建 `logs/live/pause.flag`。进程空闲时每
0.25 秒检查暂停文件，模型返回后、游戏命令发送前也检查。已经发出的请求或游戏
命令无法撤回；暂停后不发送新的动作，继续采集。恢复时自行删除暂停文件，再
重新启动外部进程；不会因删除文件就自动恢复操作。

## 运行步骤

1. 采集游戏状态，定位当前战斗的种子、楼层与房间类型，先请求 STATE 刷新。
2. 等待怪物的 DEBUG 加载占位意图更新，最多 15 秒。
3. 在支持的稳定状态生成候选，请求 Jev 选择并保存决策，再请求 STATE。
4. 下一条稳定状态必须与模型输入完全相同，否则停止；仅发送已生成的候选命令。
5. 出牌后等待 UUID 离开手牌；END 后等待回合增加。重复旧状态只刷新，绝不重复执行。
6. 确认后继续决策。奖励界面、战斗完成、退出对局、房间变化、暂停、调用上限、
   未支持状态、API 或游戏错误都会停止自动操作。命令回传等待最多 30 秒。

程序不预测抽牌、计算完整伤害引擎或处理下一场战斗。运行期间请避免手动操作
战斗；CommunicationMod 消息没有请求 ID，状态校验不能替代输入互斥。

## 记录与验证

`logs/live/states.jsonl` 保存原始状态，`latest_state.json` 保存最近状态，
`decisions.jsonl` 保存模型输入、候选与选择。`sessions.jsonl` 追加会话 ID、
调用次数、动作次数和状态：created、battle_started、request_started、
command_prepared、command_sent、action_confirmed、stopped。

prepared 表示准备发送，sent 表示已经刷新到 stdout，confirmed 才表示观察到
牌离开手牌或进入下一回合。stopped 的 reason 区分战斗结束、暂停、次数上限、
状态变化和错误。进程异常退出或日志写入失败时，不会自动重试出牌。

本地测试已覆盖连续出牌、重复消息、回合结算、奖励界面停止、次数上限、暂停、
局面变化、未覆盖状态、API 失败和子进程协议，62 项测试通过。

2026-10-04 现场完成第 1 层两只虱虫的战斗：20 次 Jev 请求、20 个动作
（14 次 PLAY、6 次 END），共 7 回合，战后生命 79/80。会话记录的停止原因是
`battle_finished`，游戏为 `room_phase=COMPLETE`、`screen_type=COMBAT_REWARD`。
未处理奖励或进入下一场；测试后已恢复只采集启动配置，无需再次重启。
这证明一场战斗流程可运行，不代表策略已经经过对照评估。
