# 整轮规划、击杀校验与经验

## 已接入的运行行为

整轮候选模拟能量、格挡、逐次伤害、痛击易伤、当前敌人意图下的承伤。当前精确分支支持邪教徒、大颚虫、盗贼、强盗、常见史莱姆与虱子，最多五个敌人；牌为打击/防御/痛击/愤怒，能力包括已验证的基础修正、蜷缩护甲、盗窃、愤怒和玩家多层护甲，遗物限燃烧之血。每张攻击的初始计算必须与游戏目标伤害预览一致，否则回到原子选择。未知牌、反伤、真菌兽死亡孢子及其他遗物等不冒充已模拟；这些条件仍可能退回逐动作路径。只有 END 可选时不请求模型。

按每个敌人剩余生命、易伤层数和玩家预计承伤删除被严格支配的计划，保留攻防取舍。确定击杀由本地验证后执行；其他计划让 Jev 一次选择整轮。药水仍作为原子候选保留，使用后重新获取状态，不会因为批处理而隐藏它们。

执行队列以牌 UUID 与目标索引表示，每步在最新合法候选中重新绑定命令。逐步确认不调用模型。生命、格挡、能量、牌身份与基础字段、能力层数、遗物计数及敌人意图偏离预测时清空队列，再规划。模型返回的 `PLAN` 只用于选择，绝不作为游戏协议命令发送。

离线协议测试已验证一次选择执行三张攻击再结束回合、费用/意图/格挡变化取消队列、痛击再打击的易伤击杀。你的第 3–5 回合真实快照能重新计算出击杀候选。这不是新版整轮执行已实机通关的证明。

## 跨局经验

停止或结束时生成 `logs/live/review-运行ID.json`，有证据的“错过确定击杀”和“重新打开已拒绝奖励”写入 `logs/live/experience.json`。相同运行、步骤不会重复计数。经验附带条件、证据范围和观察到的血量变化；血量变化不写成已经证明的反事实损失。

后续局次按战斗/奖励场景检索，把经验作为 `experience_context` 交给模型。已从真实记录保存七次错过击杀的证据。这是程序验证复盘，不是大模型自由复盘；大模型复盘服务、多回合随机推演和通用规则模拟仍未完成，API 请求不改变模型权重。

教程由用户手动确认，不加入按钮导出或自动点击。JevState 0.2 的伤害、能力描述和药水字段已有真实日志验证，数值高亮标志变化不会再误判为局面变化。伤害数值等实际字段仍严格检查。
