# 机械宽剪枝：最终由模型选择

用户最新要求：程序压到最多 32 项，但剪枝应“又笨又宽容”，不能代替模型判断战术。

## 当前实现

- 全局生成仍独立运行；32 是送给模型的选项上限，不是搜索宽度。
- 短名单函数只接收牌序和数量上限，不能读取整个局面。
- 仅对卡牌 UUID、目标、选牌 UUID、药水槽/ID/操作及 END 完全相同的命令序列去重。
- 按首动作分支轮流取样；分支内轮流覆盖不同长度和 END/观察形式。
- 保留 END、单步观察及多步牌序这些形式，不判断哪一种更有价值。
- 哈希只用于固定打破并列和展示顺序，不读取伤害、格挡、生命、名称、效果、结果预测或模型概率。
- 未知卡牌/遗物没有额外淘汰规则。最终正常只调用一次模型，返回的 choice 是最终决定。

已移除短名单中的手写规则模拟、预测致死过滤、安全候选优先、效果等价归并及特征收益选择。
致死过滤仅在本地做过实验，没有部署，现已删除；旧模拟等价归并曾用于第 06 批，已退出当前实现。
执行后的原生状态核对仍负责防止旧牌序越过实际抽牌、资源变化等边界；它不替模型选牌。
选择界面暂存模型已选的后续牌序，回到战斗后核对实际资源与合法性再继续。

## 验证要求

1. 任何最终战斗请求最多 32 项，模型没有中间淘汰赛。
2. 改动预测伤害、HP、胜负标签或“是否已建模”等元数据，短名单必须不变。
3. 正反出牌顺序不是相同命令，不能因“看起来效果相同”合并。
4. 默认战斗及短名单路径不加载 `rules.py` 或 `turn_planner.py` 的手写模拟器。
5. 固定实战见证分别检查全局枚举是否包含、最终 32 项是否包含；不能用分支覆盖冒充最优召回。

固定原生快照的机械投影保存在 `samples/shortlist_mechanical_recall.json`：
史莱姆痛击→头槌、守护者上勾拳→打击，以及死亡前存在的火焰屏障/武装保命路线。
当前这三个见证均保留（3/3），它只说明这些测试通过，不是任意局面最优召回率的保证。
全局 183 项的史莱姆例保留 32 项，其中保留了两种对应打断牌序的结束形式；
全局 99 项的守护者例保留 32 项，其中保留一个上勾拳接打击见证。
