## 已确认、尚未解决的问题

### 1. 32 项机械剪枝仍会漏掉好牌序

在三个离线对抗局面中，见证方案都在生成池里但不在最终 32 项中；其中奴隶贩子局面完整生成 2,273 项，因此不能归结为搜索截断。

新增的被拣选者实际见证更明确：完整生成 7,601 项、3,801 个展开节点、没有截断；其中“完美打击+和两张打击，不用狂暴和药水”的 12 个方案最终全部遗漏。短名单在起手覆盖、长度和资源组合之间轮换，但分支内部仍会优先取排序靠前的第二张牌，导致药水变体或火焰屏障变体挤掉不同后续牌序。

下一步应该设计并验证真正的机械后续分支覆盖，例如按每一深度的后继动作分支做宽覆盖，同时保留 END/OBSERVE 和资源变体；必须用完整池对照和未见过的对抗样本验收，不能给当前几个见证做特殊白名单，也不能重新引入收益权重。

### 2. 生成牌、抽牌和费用变化需要观察段

攻击药水、Offering、Shrug It Off 等会产生新牌或改变资源。当前协议会在原生效果后重新请求，这是正确的边界，但会暴露候选遗漏和增加模型调用次数。不要假定未观察的抽牌顺序，也不要把 `OBSERVE` 当作结束回合。

### 3. 模型侧仍有顺序敏感和机制误判

Jev 的只读实验显示，选项顺序会显著影响选择；英文展示、简化指令和明确 ID 不能稳定修复守护者/邪教徒样本。请求格式、ID 绑定和原生执行链已经验证正常。模型质量问题仍需和候选召回问题分开测量。

### 4. 跨回合局面价值仍是架构债

当前候选没有本地收益函数，`outcome()` 也没有被伪装成整局价值。模型指令包含当前牌组、遗物、怪物意图、路线和原生描述，但跨回合价值依赖模型判断。后续若增加局面价值，应作为独立、可解释的实验和指标，不能偷偷变成剪枝分数。

### 5. 参考运行和 Jev 自动运行不可混淆

冻结 Jev 复跑曾分别死在第 16、16、16、8 层；当前参考局已进入第二幕只是为了获得真实请求和机制证据。多场精英或一场 Boss 胜利都不能代替多局、多幕自动验收。
