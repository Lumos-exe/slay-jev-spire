# 战斗完整枚举与信息边界验证

日期：2026-10-05。运行策略 `enumerate-observe-3`，规则 `ironclad-6`。

## 决策合同

游戏提供当前可见状态与合法动作；程序枚举已经掌握规则的可执行牌序。只有完整搜索得到的全部不同状态方案才交给 Jev。没有 `_quality`、加权收益排序、最终 32 项截取、支配剪枝、只保留斩杀或先选进攻再单独比较 END 的阶段。候选排列顺序不表示推荐。

所有可结束的前缀都保留 END。相同完整模拟状态可以合并；手牌身份、费用、升级、能力、资源、计数器和信息边界不同的状态不合并。不同状态的优劣由模型判断。

药水不耗能量，不能把“3 能量”当成只能做 3 个动作。已支持且原生合法的药水可插在任意合法位置，可以连续使用多瓶，每个槽位只能消费一次。未知药水保留原生单步选项，用后观察，不猜它生成了什么。

`--beam-width` 仅兼容旧命令，现已忽略。时间、节点、深度限制只保护计算资源：触发时不发送残缺的计划集，改把全部原生合法单步动作交给模型，执行后重新观察。它们不表达伤害、血量或药水之间的价值换算。时间保护目前限制搜索展开，后续打包耗时单独反映在总耗时里。

若初始状态就含模拟器尚未覆盖的能力/遗物，也直接采用全部原生合法动作，不给模型附上整组残缺预测。这与执行中抽到未知牌的边界不同。第一局发现 `Sling` 的覆盖缺口后加入该路径；原始第 208 步快照回放中，12 个合法动作交给 Jev，一次请求返回 `PLAY 4 0`，没有生成模拟计划。

模型的 `choice` 只要属于给定合法候选，就是执行依据。`probabilities` 和置信度属于诊断字段；选项不是概率最大项时记录负的选择差值和警告，不覆盖选择、不停机。概率元数据无效时记为未知。不存在的候选 ID 仍被拒绝。

## 何时再次请求模型

| 情况 | 处理 |
|---|---|
| 普通攻击、防御、已知能力变化 | 继续枚举；每步仍用原生回执确认 |
| 抽取未知牌、随机消耗、随机生成牌 | 计划停在信息边界；实际结果出现后重新请求 |
| 确定的手牌内升级或指定消耗 | 可以把具体目标纳入计划；遇到原生选择界面绑定该牌，再核对状态 |
| 消耗触发未知抽牌 | 停在抽牌边界，不能把消耗本身当作“效果已全部算完” |
| 已明确放回牌堆顶部后再抽取它 | 已知部分可以继续；再抽未知部分时停止 |
| 原生状态与计划预测不一致 | 作废剩余计划，按真实状态重新决策 |

`checkpoint` 不是结束回合，不是必死，也不是未知效果价值为零。模型输入继续区分游戏字段、规则算术预测及未知部分，不提供综合收益分数。

小地精 `Angry` 的力量增长属于已知状态变化，已交给现有 `refresh_intents` 重算意图伤害；仅缺少原生基础伤害时才保留观察边界。原先无条件停止的规则错误导致痛击+后的顺劈斩斩杀从未进入候选。

## 测试与实战

最终本机测试合计 316 passed、3 skipped（主套件 313 项通过，随后新增的 3 项模型选择权测试通过）；Windows 最终全套 319 passed。核心断言包括：5 张 1 费牌在 3 能量下覆盖全部 26 种可打子集、三瓶药组合与先出牌后用药、禁止重复使用同一槽位、超预算时全部原生动作仍交给模型、真实抽牌结果到达后第二次调用选择器、初始状态覆盖不足时不用残缺预测，以及原生事务确认。

两局正常游戏均已结束。第一局第 16 层战败，221 次原生提交，无技术停止。第二局在第 5 层出现一次 `selection_error`：旧校验拒绝了“不是概率最大项”的合法模型选择。该次请求尚未发送游戏动作；保存现场、修复并通过真实 Jev 回放后，重载控制器，在同一战斗的相同生命与回合恢复，没有重开游戏。第二局随后击败史莱姆 Boss，第二幕第 20 层战败；合并恢复前后共 321 次原生提交、1 次技术停止、0 个重复提交 ID。两局共 542 次提交，通关 0/2。

第二局的日志因此有两个控制器运行标识：`b8633125-61c9-4478-9e98-0864ddc3f398`（修复前）和 `82371c54-66c6-4edc-b3ca-5f7a795e027e`（恢复后）。统计必须合并两个片段，并保留那次技术停止。

上下文超限时仍可能需要多次模型调用：保存的第 67 步有 94 个候选，完整输入触及服务限制，回放进行了 10 次请求，包括被拒绝的请求和模型分组比较；每个候选都参与比较。它不是本地枚举耗时大，也没有因此按收益裁掉候选。分组比较的最终概率只属于最终候选，不是全体方案的胜率。

## 后续等待时间调查

第二局恢复后的 127 次单步回退均由未建模状态触发，主要问题是香炉 `Incense Burner`。已对照原生方法确认香炉在 `atTurnStart` 触发、投石索 `Sling` 在 `atBattleStart` 触发；当前回合已生效的能力由游戏状态提供，不应因此逐张请求。增加了触发阶段声明，下一回合的遗物触发仍明确列为未来信息，不伪装成已完成的跨回合模拟。
