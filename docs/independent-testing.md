# 自己启动与测试

1. 保持 Steam 已启动并登录，正常退出当前游戏。
2. 双击项目根目录 `play_jev.cmd`。它检查游戏与 Mod 文件，安装本地 JevState 数值导出 Mod、备份通信配置，启用 Jev（默认最多 500 次请求），清除上次暂停标志，再启动带 BaseMod、CommunicationMod、JevState 的游戏。
3. 到主菜单后点击“继续”，不要手动操作局内选择。代理自动处理当前支持的奖励、选牌、地图和战斗。
4. 双击 `status_jev.cmd` 查看最后采集时间、界面、请求数和停止原因。需要暂停时双击 `pause_combat.cmd`；新版进程用 `resume_jev.cmd` 恢复，并取得额外一段请求预算。

这些操作无需等待 Codex 或在聊天里确认。游戏已经运行时，启动器提示正常退出，不强制关闭，也不修改配置。再次启动会获得新的 500 次请求预算。每个进程另有 90 分钟和 2000 个动作的上限；恢复沿用时间和动作上限，追加最多 500 次请求，不再每 20 次暂停。

代理从同一种子、角色、难度的已确认日志恢复近期动作和跳过奖励记忆。奖励界面先自动领取金币和有空栏位的药水（添水遗物阻止领取时除外），每次仍核对实际金币或药水变化；选牌、遗物与钥匙等取舍交给模型。已明确跳过的单组卡牌奖励不会再次打开；存在多组匿名奖励时不盲目隐藏，依靠重复局面保护停止。相同游戏摘要及候选第三次出现时会在请求前停下。状态窗口分别统计请求失败、重复局面请求和已确认动作；重复局面不一定是无效决策。

JevState 导出当前手牌字段、其他牌的基础数值和原始描述，以及双方能力的实时说明、遗物说明和药水效果。标准卡牌模板可解析。手牌目标伤害预览通过卡牌副本调用游戏的 `applyPowers`、`calculateCardDamage`，包括该计算中的能力修正；不修改原手牌。预览仍不等于最终扣血或多段动作模拟，不能再次重复乘弱化/易伤。其他自定义模板保持未知。开发者重新构建用 `tools/build_jev_state.ps1`（需要 JDK）；日常启动使用已构建的 `build/jev-state/JevState.jar`，不需要编译。JevState 0.2 已在真实战斗中验证加载及数值导出；此次整轮规划已通过离线回放，尚需真实战斗验证。教程由用户手动点击。

模型输入包含整副牌、抽弃消耗牌堆、双方能力与敌人意图、近期动作及整场战斗生存目标，要求考虑未来回合。现已针对邪教徒、大颚虫、盗贼、常见史莱姆与多只虱子，以及打击/防御/痛击/愤怒和已验证能力与遗物条件搜索整轮候选；确定击杀本地执行，其他计划由模型一次选择整轮，逐步执行时按 UUID 重新绑定位置并核对预期状态。费用、能力、伤害或敌人意图改变则重新规划。复杂卡牌、未知规则及随机效果仍回到逐动作路径。详细覆盖与验证见 [整轮规划与经验](turn-planning.md)，不能称为通用完整战斗规划器。

新版支持原生事件、商店、营火、特殊选牌和通用铁甲战斗卡牌；字段错误、请求预算、暂停、状态变化或无法确认动作会停下，状态查看窗口会显示原因。双击 `play_new_jev.cmd` 明确开始新的铁甲 A0 对局，无需点击主菜单；新局可能替换现有存档。继续现有存档仍用 `play_jev.cmd`，主菜单点击“继续”。

启动日志在 `logs/launch/`，游戏状态与决策记录在 `logs/live/`。状态窗口展示历史快照，不把旧日志当成正在运行的证明。导出时间线见 [跨界面运行说明](run-loop.md)。

启动使用 ModTheSpire 的 [官方命令行参数](https://github.com/kiooeht/ModTheSpire/wiki/Command-Line-Arguments)，直接选择三个 Mod 并跳过启动器和片头。首次加载新数值 Mod 需要重启游戏；仅恢复 Python 进程不会加载 Java 补丁。

开发验证优先使用 pytest 和离线协议回放。真实游戏启动可以通过命令完成，新局可以通过协议开始；当前 Codex 环境不提供原生窗口点击能力，现有存档的“继续”仍未接入，所以暂时不能承诺独立完成所有真实游戏测试。
